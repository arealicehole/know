## EXEC SUMMARY (for Frank — read this first)

The Bible v2.1's chat-discovery doctrine is directionally right and most of it is still valid, but **five things have changed or been re-verified since the June/October touches and the chat sections need a patch**:

1. **UCP is now an official, live Google-led standard** (launched 2026-01-11, spec 2026-01-23; co-developed with Shopify/Etsy/Wayfair/Target/Walmart; endorsed by Visa/Mastercard/Stripe/Amex). It is not just our internal convention. Google is rolling out a **UCP integration hub in Merchant Center (US first, AU/CA next)** and UCP-powered checkout/Buy buttons in **AI Mode + Gemini**. Our PJ `.well-known/ucp` (ucp/1.0, 2026-05-11) and Maza's discovery stub both pre-date the formal spec publication. **Bible should cite the standard and the Merchant Center path.**
2. **ChatGPT's agentic-commerce story pivoted in March 2026.** In-chat "Instant Checkout" (Sept 2025) was **pulled back ~4 months later (Mar 4, 2026)**; OpenAI now pushes **ACP-powered product discovery** (comparison surfaces, feed-based merchandising, merchant hand-off to the merchant's own site/app). Implication: *discovery + comparison* is where chat-UI lead handoff lives now; *in-chat checkout* is a narrow, platform-controlled surface.
3. **Yelp is now a first-class local-data source for ChatGPT** (licensing deal announced ~Jul 23, 2026: 330M reviews / 8M+ listings; Reservations + Waitlist integrated in ChatGPT by Aug 10, 2026; "Request a Quote" for local services). **A strong Yelp profile is now part of ChatGPT discovery for local businesses** — the Bible treats Yelp as a "sameAs link," not a recommendation source. This is a material change for Maza-class businesses (and for PJ: get on Yelp).
4. **The biggest measurable finding: semantic relevance beats traditional local-SEO authority in LLM "near me" answers.** A 104,855-citation study (Oct 27–Dec 3, 2025) across OpenAI/Gemini/Perplexity/Grok/Copilot/Google AI Mode found intent-match is the dominant rank driver; domain authority, schema markup, and map rank show weak/inconsistent correlation. This **re-ranks our lever stack**: page-level content that matches the query wins; schema is an entity-disambiguation aid, not a ranking engine.
5. **Our own stack moved since the last audit (t_64b6e1c1, 2026-10-28):** PJ now ships `llms.txt` (200, 1,801B — "Agent endpoints" section pointing to UCP/specs), a `Dataset`+`DataCatalog` JSON-LD catalog, full `Product`/`Offer`/`AggregateOffer`/`ItemList` schema with prices, and a `/api/specs` index (8 products). Maza now ships `Menu`+`MenuSection`+63×`MenuItem`+65×`Offer` JSON-LD with **real prices in the menu markup and body** (was 0 on home), and its UCP manifest now carries a live `lastUpdated`. Both sites return 200 to GPTBot/OAI-SearchBot/PerplexityBot UAs (edge does not challenge them).

**What is NOT yet proven:** any causal link between any single lever and a citation, including llms.txt → ChatGPT leads (PJ received ChatGPT leads before llms.txt existed). Multi-engine citation battery is still un-executed. Those stay "unknown," not "true," in the Bible.

## A) Principles for big-box chat-UI discovery (late 2026)

Each principle: what it is, tag (verified/likely/speculation), and what an operator does. "Verified" = confirmed by primary vendor docs or our own live probe this run; "likely" = corroborated by 1+ reputable secondary source, mechanism consistent; "speculation" = plausible, not yet demonstrable.

**P1 — Answer engines are retrieval-first, not memory-first, for local queries.** [verified]
Every major engine (ChatGPT-search, Claude web search, Perplexity, Grok web search, Google AI Mode/Overviews) grounds local answers in live/web retrieval at answer time (OpenAI documents OAI-SearchBot for search; Anthropic documents Claude-SearchBot; Perplexity documents PerplexityBot; xAI documents web_search; Google's AI Mode reads its index). The engine can only say what it can reach and read. *Operator action: assume the answer is built from pages fetched at query time — optimize for fetch + quotability, not just index presence.*

**P2 — Access is the gate: crawler reach + edge 200, in that order.** [verified]
OpenAI states opted-out sites (OAI-SearchBot blocked) are not shown in ChatGPT search answers (though they may appear as navigational links). Perplexity documents PerplexityBot as non-training. Anthropic documents Claude-SearchBot/Claude-User. Our live probe: PJ and Maza both return **200** to GPTBot, OAI-SearchBot, and PerplexityBot UAs today — both sites are *reachable* by the answer bots. [verified — this run]
Cloudflare now ships per-class AI-bot policy (Search/Agent/Training, each allow/block) and **on 2026-09-15 changed new-domain defaults so Training/Agent bots are blocked on ad pages** — meaning the default edge posture is drifting *toward* blocking; a site's robots.txt allow can be silently overridden at the edge. *Operator action: robots.txt allow is necessary, not sufficient — acceptance test is a 200 at the edge for each answer bot UA.*

**P3 — Semantic relevance (intent match) is the dominant citation driver; traditional authority signals are secondary.** [likely]
The 104,855-citation near-me study (Oct–Dec 2025, six platforms) found: intent-matching pages rank highest across platforms; domain authority and schema markup show weak/inconsistent correlation with citation position; GBP quality is a modest, platform-dependent factor; freshness matters most for Gemini. Perplexity's retrieval-first design ("engine is loyal to whatever it can ground right now") explains why a small local page can outrank a big directory on a specific query. *Operator action: per-intent pages that directly answer a question the way the user phrases it beat generic category pages. This is the Information Gain principle, now with data.*

**P4 — Entity identity (NAP + sameAs + corroboration) is the disambiguation layer, not the ranking layer.** [likely]
AI extractors resolve a brand to an entity before it can be cited; sameAs is documented by Google as a behind-the-scenes disambiguation signal; resolution requires *consistent evidence across multiple sources* (one sameAs is not enough; broken sameAs reads as active disconfirmation). The 2024-era advice "stuff every social profile in sameAs" is now considered a missed-opportunity pattern — extractors weight authoritative identifiers (GBP, registry, maps, major platforms) over social links. *Operator action: max out sameAs with *authoritative* targets first (Maps, Apple Maps, Yelp, delivery platforms, GBP/registry) and keep NAP byte-identical everywhere.*

**P5 — Reviews/ratings are a recommendation signal for ChatGPT local answers, via Yelp licensing and profile data.** [likely]
Yelp–OpenAI deal (Jul 2026): ChatGPT surfaces Yelp reviews/ratings/photos in local answers; Yelp is "the most cited home services discovery platform, 3.4× lead" per Yelp's own AI-citation claim. SOCi correlation: ChatGPT-recommended locations average 4.3 stars. *Operator action: treat Yelp + Google review profiles as *answer-source* surfaces (claim, complete, maintain velocity), not just backlinks. Caveat: the 3.4× is a vendor claim; the 4.3★ is a vendor correlation — neither proves causation.*

**P6 — Two surfaces, two jobs (keep, from v2.1).** [verified — re-probed]
Identity/discovery surface (llms.txt, typed Restaurant/LocalBusiness schema, address, hours, rating, sameAs) decides *whether you're found*; transaction/offer surface (UCP manifest, specs, visible prices, Offer/MenuItem schema) decides *whether the answer can quote prices and hand a lead to an order/quote*. Neither reference site runs only one; both now run both (see §D). *Operator action: ship both; measure them separately.*

**P7 — Machine manifests must be discoverable from the first-contact surface.** [likely]
An agent hitting a site reads home + llms.txt first; a UCP/specs endpoint that is not linked from llms.txt or schema is only used if the agent independently probes `.well-known/ucp`. PJ's llms.txt now carries an "Agent endpoints" section; that linkage is the pattern. [verified that ours do this; likely that it matters — no engine has documented that it reads llms.txt, see P8] *Operator action: every machine manifest gets a pointer in llms.txt and, where applicable, schema (Dataset/DataCatalog, hasMenu).*

**P8 — llms.txt is a convention, not a standard with documented engine consumption.** [verified]
llms.txt (llmstxt.org, v2) is a community convention (format: H1 + description + `##` sections/links; optional llms-full.txt). **No major engine (OpenAI/Anthropic/Google/Perplexity/xAI) documents that it reads llms.txt.** Adoption studies (e.g., SERanking ~300k-domain scan) show it's present on a minority of large sites. It does not control robots, does not block training, does not replace sitemaps. *Operator action: ship it (cheap, first-contact card, human+agent readable) but do NOT claim it is a citation lever or an access-control file.*

**P9 — Per-engine behavior differs; parity is the honest goal.** [likely]
ChatGPT search may merge its own OAI-SearchBot index with outside providers (Bing is named in OpenAI docs); Perplexity runs its own 200B+-URL index; Gemini/AI Mode rides Google's index + Maps/GBP data; Grok has no documented crawler (reported tokens: GrokBot, xAI-SearchBot) and a separate X-content channel robots can't touch; Claude documents three separately-controlled crawlers. Citation-display differs (inline vs sources panel vs numbered footnotes). *Operator action: verify per engine; don't tune doctrine to one engine's observed quirk.*

**P10 — Commerce handoff in chat UIs in late 2026 = discovery/comparison + handoff to merchant (or a platform-owned checkout where available), not universal in-chat checkout.** [verified]
OpenAI pulled back Instant Checkout (Mar 4, 2026) and now runs ACP-based discovery/comparison with merchant hand-off; Google's UCP checkout exists but is gated (US/CA/AU, participating merchants, AI Mode/Gemini surfaces only). For a local service business, "lead handoff" in chat = the answer names the business + phone/quote/order URL, or a platform-embedded action (Yelp Request a Quote, Reservations). *Operator action: publish phone, quote path, and order URL in the answer-readable layer (llms.txt + schema + body); treat platform-owned checkout as a bonus surface, not the strategy.*

**Media/news (§8) — where rules differ:** [likely]
- News sites: Google's AI Overviews cite from the index + its own freshness weighting; the §8 media doctrine (SSR, feeds, llms media profile, UCP-gate-for-media) still holds — but the *citation* driver for news is freshness + topical authority in the index, not agent manifests. UCP does not apply to news; "UCP-gate-for-media" in the Bible should stay scoped to media-with-commerce (e.g., shop-in-article), not news.
- One difference that matters: Perplexity shows a "Trusted/Government/Academic" source label (domain-level, not claim-level) — no local-business path to earn it; don't chase it.

**Answer/browse/citation vs training:** [verified split]
Each vendor splits crawlers into (a) training (GPTBot, ClaudeBot, Google-Extended), (b) search/answer (OAI-SearchBot, Claude-SearchBot, PerplexityBot, xAI-SearchBot), (c) user-triggered fetch (ChatGPT-User, Claude-User). Only (b) + (c) affect *citations*; (a) affects long-term latent knowledge and is a separate data-governance decision. Never conflate them in doctrine.
